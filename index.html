A ComfyUI image-generation workshop for six students.

Preparing the workshop: five priorities

  • ✓

    Get the workflow running

    Diagnose the custom-node error, test the fix and apply it across the lab machines.

  • ✓

    Work within the available GPU memory

    Test a smaller training configuration and agree a fallback that supports the session’s aims.

  • ✓

    Check the model’s suitability

    Review licensing and data provenance; discuss any gaps with the academic before use.

  • ✓

    Make it approachable and accessible

    Check students’ needs and prepare a working example, clear instructions and a short glossary.

  • ✓

    Leave a setup others can use

    Record the tested configuration, fixes and recovery steps so the next session is easier to prepare.

Before, during and after the workshop

01
Before

Prepare for participation

  • Brief the academic on changes and constraints.
  • Check accessibility: seating, screen magnification, input devices and familiarity with the lab interface.
  • Prepare a quick-reference handout, a preloaded workflow and a tested checkpoint.
02
During

Support exploration

  • Begin with a guided walkthrough.
  • Invite peer support between students with different levels of experience.
  • Stay available and step in before confusion becomes frustration.
03
After

Make learning reusable

  • Record the environment, versions, model checksums and licensing decisions.
  • Gather feedback and update the runbook.
  • Build a library of tested workflows and guidance for independent practice.

Lower the threshold of entry without lowering the ceiling of what’s possible.

Preflight — test the actual ComfyUI workflow

Proposed checks for the workshop scenario:

1. Launch ComfyUI and load the workshop’s workflow JSON.
2. Check that the required models and custom nodes are available; inspect startup errors.
3. Run a small example with the intended settings. Check the output, runtime and GPU memory use.
4. Repeat the test on each student machine, recording versions and any fixes.
This diagnostic is a proposed approach, not a completed lab test. My separate LoRA experiment ran through Python scripts on a rented GPU.

Cloud GPU — conditional fallback

Must be agreed and tested before the workshop:

Procurement and budget approved.
Data handling and institutional requirements checked.
Environment tested with the exact workshop workflow.
Existing institutional computing provision considered.
Use this route only when the prerequisites are met. Otherwise, agree an alternative with the academic.
Cloud environment — optional practical

Additional GPU capacity, with an optional guided introduction to remote computing.

Proposed allocation: $5 per student; $30 for six. Confirm GPU, storage and transfer charges.
Foundation: a pre-tested Docker image with ComfyUI and the required dependencies.
1. Launch a GPU instance and monitor costs.
2. Use the remote terminal to download, inspect and run a prepared Python script from a verified repository.
3. Save and download outputs, then remove unused resources.
Teach these steps when remote computing supports the learning objective. Otherwise, provide the environment ready to use.

Revolutionary Drapery: a LoRA experiment

Adapting an existing model

SDXL adapted using Hugging Face PEFT (LoRA), trained on 20 public-domain images using an NVIDIA RTX 3090 rented through Vast.ai.

Small adapters are trained while the base model’s weights remain frozen.

  • Resolution: 1024 × 1024
  • LoRA rank: 8 · training steps: 500
  • Batch size: 1 · gradient accumulation: 4
  • FP16 · gradient checkpointing enabled

Columns: base → 100 → 300 → 500 steps. Rows: body, cloth and space. Each row uses the same prompt and seed across checkpoints.
